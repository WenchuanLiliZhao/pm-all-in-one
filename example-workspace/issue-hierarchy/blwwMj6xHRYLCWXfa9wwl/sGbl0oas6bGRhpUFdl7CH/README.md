## What to do

Unify external name surfaces on **`pm-all-in-one`**: display name, CLI, npm package, repo slug, and app bundle. macOS `appId` is **`com.pm-all-in-one.desktop`**. **`local-pm`** stays the workspace/category label for this library format — not the product name. Check README, About, installer filenames, and Pages copy; remove the former spaced display name and stale aliases (e.g. CLI as `local-pm`).

## Why

Multiple names for the same product make the download page, Release, and system “Privacy & Security” prompts disagree, which weakens the “this is real software” feeling. Naming is the cheapest trust and brand alignment.

## Non-goals

- Do not rewrite product positioning copy (belongs to README / narrative subtasks)
- Do not run a trademark registration or domain campaign

## Done when

- Short convention documents the single product name `pm-all-in-one`, where `local-pm` still applies (workspace type), and `appId`
- Spot-check of external touchpoints is consistent: README, About, installer/app display name, Pages (if present) — no conflicting old names
- `appId` fixed as `com.pm-all-in-one.desktop` (or the final value clearly documented and used everywhere the same)
